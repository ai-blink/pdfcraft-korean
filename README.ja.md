# PdfCraft Korean

[English](README.md) · [한국어](README.ko.md) · [简体中文](README.zh-CN.md) · [日本語](README.ja.md)

**[@ai-blink](https://github.com/ai-blink) による韓国語 PDF テキスト編集の改善プロジェクトです。**

[PdfCraft](https://github.com/storytold/pdfcraft) を基に、既存の韓国語テキストの編集から保存、再読み込み、検索、選択、コピーまでを改善した独立派生プロジェクトです。元の PDF エンジン、アプリケーション、先行変更の著作権は各著作者に帰属します。

## @ai-blink の貢献

- 上流の [PR #6101](https://github.com/storytold/pdfcraft/pull/6101) から韓国語編集の変更を選別して統合し、検証基準のタイ語フォールバック、異体字セレクタ、行処理を維持しました。
- 固定バージョンの NanumGothic を文書と編集欄で使用し、対応する漢字には日本語フォントを利用しました。
- 現代ハングル字母の合成と UTF-8 スタイル位置の対応を改善しました。スタイルだけの編集、不正な元テキスト範囲、大きすぎる分解入力、変更のないハイフン除去テキストの回帰も修正しました。
- Windows Hyper-V ゲストで編集 → 保存 → 閉じる → 再読み込み → 描画確認 → 検索ハイライト → 選択 → コピーを実行し、実際のクリップボードと比較しました。
- ローカル試験コントローラーの STA クリップボード処理による Ctrl+C ACK タイムアウトを診断し、メッセージ処理を修正しました。これはアプリ本体とは別の試験環境の修正です。

## 検証状況

韓国語実装の [`df68b4d`](https://github.com/ai-blink/pdfcraft-korean/commit/df68b4dc70672482766c2a71dedfe0feea3e29ca) で **3,945 テストが成功**し、**既存の 9 テストは除外**されました。変更したクレートの clippy、fmt、layers、assets、parity、wasm 検査も成功しました。新しい回帰テストは修正前に失敗し、修正後に成功しました。

合成済みハングル、分解字母、ハングルと漢字の混在文について、保存したファイルの再読み込み、描画、検索位置、選択、ゲストの実際のクリップボードを確認しました。修正済みコントローラーでは **Ctrl+C ACK とクリップボードの完全一致が 9/9 回成功**しました。韓国語フォントのないビルドは明確なエラーを返し、元文書と編集内容を保持しました。

これらは当該実装スナップショットの結果です。その後の公開用ブランド変更について、GUI 全体を再検証したという意味ではありません。検証した基準は最新の upstream main とも異なります。[検証詳細と再現手順](docs/KOREAN-VALIDATION.md) を参照してください。

## ビルドと使用方法

Rust **1.95 以降**と各プラットフォームのネイティブビルドツールが必要です。英語の [固定フォント・翻訳を含むビルド手順](README.md#build-with-korean-fonts-and-translations) を使用してください。フォントと翻訳を指定リビジョンで取得し、`CRAFT_FONTS_REQUIRED=1` と `CRAFT_I18N_REQUIRED=1` でビルドします。

1. 合成 PDF を開き、**Edit text** で既存の文を選択します。
2. `안녕하세요. 한글 편집 검증 2026, 계약 금액 1,234,567원.` に置き換えます。
3. 保存して文書を閉じ、保存した PDF を改めて開きます。
4. 描画を確認して `한글 편집` を検索し、文を選択してコピーします。
5. 実際のクリップボードを合成後の期待文字列と比較します。分解字母や漢字混在文でも繰り返します。

現代ハングル字母は保存・コピー時に合成されます。一般的な NFC/NFKC 正規化や、すべての分解形検索クエリの等価性を保証するものではありません。現在の Web 用フォント構成には韓国語フォントがありません。wasm ビルド成功は Web での韓国語編集対応を意味しません。この変更を含む新しい配布パッケージやリリースはまだありません。
